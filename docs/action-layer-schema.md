# Action-layer JSON schema

This documents every action op the action layer (`src/libs/actionlayer/`) supports, as run by
`seamly2d-actiond` (`src/app/actiond/`) — either as one batch via the one-shot `--actions <file>`
CLI mode, or as a line in the persistent NDJSON daemon's request stream (see
[Session protocol](#session-protocol) below). Each op shows one example JSON action object; a
trailing `?` on a field name in a handler's own header comment means optional. Optional fields not
shown in an example use their documented default.

This file is generated by hand from `src/libs/actionlayer/action_registry.cpp`'s registration list
and each handler's own header doc-comment (`src/libs/actionlayer/handlers/*.h`) — those headers
remain the source of truth for exact field names/types; re-check them if this file and the code
ever disagree.

## Session protocol

`seamly2d-actiond` has two modes:

- **One-shot** (`--actions <file>` given): load a pattern, run that one script, optionally save
  (`--save-pattern <path>`), print the JSON result, exit.
- **Persistent NDJSON daemon** (`--actions` omitted): `--pattern` and `--measurements` become
  optional (omit `--pattern` to start from an empty pattern), `--output-dir` (default `./output`)
  is where relative `render.snapshot`/`session.save` paths land, and the process reads one JSON
  request per stdin line, dispatches its `"actions"` array, and writes one JSON response per
  stdout line, until stdin reaches EOF or a `session.close` action is processed.

Request line:

```json
{"id": "batch-1", "onError": "abort", "actions": [{"op": "basePoint", "name": "A", "x": 0, "y": 0}]}
```

- `id` (optional, any JSON value): echoed back verbatim in the response, `null` if omitted.
- `onError` (optional, default `"abort"`): `"abort"` stops dispatch at the first failing action
  (`"results"` covers only what actually ran); `"continue"` runs every action regardless.
- `actions` (required, array): each entry is one action object, `{"op": "...", ...}`.

Response line (always one line, compact JSON, flushed immediately):

```json
{"id": "batch-1", "status": "ok", "appliedCount": 1,
 "results": [{"op": "basePoint", "index": 0, "status": "ok", "result": {"id": 1, "name": "A"}, "error": null}],
 "error": null}
```

- `status`: `"ok"` (every action in the request ran and succeeded), `"partial"` (`onError:
  "continue"` and at least one action failed), or `"error"` (aborted early, or the request itself
  was malformed — see below).
- `appliedCount`: number of actions that succeeded.
- `results`: one entry per action actually dispatched, each `{"op","index","status":"ok"|"error",
  "result": <payload or null>, "error": <null or message/structured object>}`.
- `error`: top-level failure reason for something *outside* action dispatch — a JSON parse
  failure, or a request missing/mistyping `"actions"`. `null` on every other path (per-action
  failures live inside `results`, not here).

`session.close` (see below) ends the loop after its batch's response is written.

**One-shot mode's response shape is different from the daemon shape documented above.** One-shot
mode (`--actions <file>`, no daemon) prints `ActionEngine::run()`'s own raw output directly, with
no `id`/`status`/`appliedCount` wrapper and no `index` per result:

```json
{"results": [{"op": "basePoint", "ok": true, "value": {"id": 1, "name": "A"}, "error": ""}]}
```

Only the persistent daemon (`SessionServer::processLine()`/`remapResult()`,
`src/app/actiond/session_server.cpp`) remaps this into the `{id,status,appliedCount,results:[
{op,index,status,result,error}],error}` shape shown above. A caller driving one-shot mode should
read `result.ok` (bool) and `result.error`, not `result.status`; a caller driving the daemon should
read `result.status` (`"ok"|"error"`) and `result.result`, not `result.value`. See
`tests/actionlayer/actionlayer-tests/expected/*/response.json` for real one-shot examples and
`tests/actionlayer/scripts/` for real daemon examples.

## Error handling

Every op returns a failure the same general way: `ok: false` (one-shot) / `status: "error"`
(daemon), with the failure detail in `error`. That `error` value is either a **plain string**
(most simple validation failures) or a **structured object** with at least `"type"` and
`"message"` fields (failures worth letting an automated/AI caller branch on programmatically).
Which shape a given failure uses is a property of *where* the check lives, not of severity:

- **Plain-string errors** come from a handler's own field validation, run *before* it resolves any
  name or calls into Seamly2D core -- e.g. `line` requiring non-empty `"firstPoint"`/`"secondPoint"`,
  `basePoint` requiring `"x"`/`"y"`/a non-empty `"draftBlock"` name, `endLine` requiring a `"length"`
  formula. These are deliberately terse ("X requires non-empty Y") rather than typed, since they are
  malformed-input errors a caller fixes once by reading the docs above, not errors a program needs
  to branch on by category.
- **Structured errors** (`{"type", "message", ...op-specific fields}`) cover every failure mode
  that *is* worth branching on:

  | `type`                  | Thrown/produced by                                                    | Extra fields |
  |--------------------------|------------------------------------------------------------------------|--------------|
  | `nameResolution`         | `NameResolver::idForName()`/`nameForId()` (`ActionResolverError`, caught in `ActionEngine::run()`) | `name`, `kind` (`"notFound"` \| `"wrongScope"` \| `"duplicate"`), `knownNames`, `foundInScope` (only for `wrongScope`) |
  | `formulaError`           | A malformed formula string, caught from `qmu::QmuParserError` (see below) | `op`, `expr` (the sub-expression qmu was evaluating) |
  | `draftBlockExists`       | `basePoint` naming a `draftBlock` that already exists (or is empty)   | `draftBlock` |
  | `noIntersection`         | `lineIntersect` naming two exactly-parallel lines                     | — |
  | `unsupported`            | `point.edit` naming a field that doesn't apply to the point's actual tool type | — |
  | `missingMeasurements`    | `measurements.load`/`.sync`/`.recompute` against a file missing a measurement the pattern requires | `missing` (array of names) |
  | `measurementTypeMismatch`| A measurement file supplying a value of the wrong type for a name the pattern expects | `expected`, `actual` |
  | `coreException`          | Any `VException` (or subclass: `VExceptionBadId`, `VExceptionWrongId`, `VExceptionObjectError`, `VExceptionEmptyParameter`, `VExceptionConversionError`, ...) that reaches `ActionEngine::run()`'s own catch clause uncaught by the handler itself | `detail` (only if the exception's own `DetailedInformation()` is non-empty) |
  | `unhandledException`     | Any other `std::exception` that reaches `ActionEngine::run()`'s catch clause uncaught | — |
  | `unknownError`           | A non-`std::exception` C++ exception (`catch (...)`) escaping a handler -- should never happen in practice | — |

  An "Unknown action op" failure (an `"op"` string absent from `ActionRegistry`) is its own case:
  a plain string, produced directly by `ActionEngine::run()` before any handler lookup happens at
  all, naming the offending op.

**Where `VException` handling actually lives.** Seamly2D core throws `VException` (and its
subclasses, `src/libs/ifc/exception/vexception*.h`) from tool-creation calls like
`VToolLine::Create()`/`VToolEndLine::Create()` on malformed pattern data (bad id, wrong object
type, missing DOM attribute, ...). Three layers guard against one ever reaching a caller as a raw
crash:

1. **Every handler that calls a real `Create()`** wraps that call in its own local
   `try { ... } catch (const VException&) catch (const std::exception&) catch (...)` (see
   `line_handlers.cpp`, `point_handlers.cpp`, `formula_point_handlers.cpp`'s shared `runCreate()`,
   and every other mutating handler), converting the failure into an `ActionResult::failure()`
   before it ever reaches `ActionEngine::run()`. This is the primary, expected path -- almost
   every `VException` a caller will ever see was caught here, not by layer 2.
2. **`ActionEngine::run()` itself** (`action_engine.cpp`) additionally catches
   `ActionResolverError`, `VException`, `std::exception`, and `...` around every handler
   dispatch, as a safety net for a handler added later without its own local catch. This is what
   produces the `coreException`/`unhandledException`/`unknownError` types above.
3. **The process-level catches** in `main.cpp` (one-shot mode, around the whole run) and
   `session_server.cpp`'s `processLine()` (daemon mode, around one request line) are the final,
   rarely-exercised nets -- they exist for a failure outside action dispatch entirely (a pattern
   file that fails to load/parse), not for a per-action failure, which layers 1-2 above already
   convert to a normal JSON result.

**Formula errors specifically:** `VAbstractTool::CheckFormula()`
(`src/libs/vtools/tools/vabstracttool.cpp`) evaluates every formula string via
`Calculator::EvalFormula()`. On a parse failure it checks `qApp->isAppInGUIMode()` -- `actiond`
(`actiond_application.cpp`) always reports `false`, so `CheckFormula()` never shows a "fix the
formula" dialog and always re-throws `qmu::QmuParserError` instead, which layer 1 above (each
formula-bearing handler's `runCreate()`) catches into the `formulaError` type. A broken formula is
therefore always a clean, fast JSON failure -- never a blocking dialog and never a process crash;
see `tests/actionlayer/actionlayer-tests/fixtures/08_error_bad_formula.json` for a live example.

## Read-only introspection

**`pattern.dump`** — every geometry object plus the tool-history list.
```json
{"op": "pattern.dump"}
```

**`pattern.listMeasurements`** — every measurement variable currently attached to the pattern.
```json
{"op": "pattern.listMeasurements"}
```

**`pattern.listTools`** — the static list of every op name this action layer supports.
```json
{"op": "pattern.listTools"}
```

**`pattern.resolveName`** — resolve a name to its internal id/type.
```json
{"op": "pattern.resolveName", "name": "A1"}
```

**`render.snapshot`** — rasterize the draft scene to an image file.
```json
{"op": "render.snapshot", "path": "square.png", "width": 400, "height": 400}
```

## Points

**`basePoint`** — new draft block's anchor point (only the first point of a new piece; a draft
block cannot already contain one).
```json
{"op": "basePoint", "name": "A", "x": 0, "y": 0, "draftBlock": "Front"}
```

**`endLine`** — point at formula distance + angle from a base point.
```json
{"op": "endLine", "name": "B", "basePoint": "A", "length": "100", "angle": "0"}
```

**`alongLine`** — point at a formula distance along an existing line.
```json
{"op": "alongLine", "name": "M", "firstPoint": "A", "secondPoint": "B", "length": "AB/2"}
```

**`normal`** — point at formula distance along the normal to a line (numeric angle offset).
```json
{"op": "normal", "name": "N", "firstPoint": "A", "secondPoint": "B", "length": "20", "angle": 0}
```

**`bisector`** — point at formula distance along an angle bisector.
```json
{"op": "bisector", "name": "Bi", "firstPoint": "A", "secondPoint": "B", "thirdPoint": "C", "length": "20"}
```

**`shoulderPoint`** — point at formula distance from a shoulder point toward a line.
```json
{"op": "shoulderPoint", "name": "Sh", "p1Line": "A", "p2Line": "B", "pShoulder": "C", "length": "20"}
```

**`lineIntersect`** — intersection point of two existing lines (no formula).
```json
{"op": "lineIntersect", "name": "X", "p1Line1": "A", "p2Line1": "B", "p1Line2": "C", "p2Line2": "D"}
```

**`point.edit`** — mutate an *existing* point's formula/coordinates in place (same id; drives the
same DOM-write-plus-recompute path a GUI dialog's "Apply" uses). `x`/`y` only apply to a
`basePoint`-created point (required together); `length` applies to any formula-length point
(`endLine`/`alongLine`/`normal`/`bisector`/`shoulderPoint`); `angle` currently only applies to an
`endLine`-created point. An unsupported field for the named point's actual tool type is reported as
a structured `"unsupported"` failure, not a silent no-op.
```json
{"op": "point.edit", "name": "D", "length": "0"}
```

## Cut / intersection points

**`cutSpline`** — point cut along a spline/splinePath/cubicBezier/cubicBezierPath at a formula
length from one end.
```json
{"op": "cutSpline", "name": "Cut1", "curve": "Curve1", "direction": "forward", "length": "50"}
```

**`cutArc`** — point cut along an arc at a formula length from one end.
```json
{"op": "cutArc", "name": "Cut2", "arc": "Arc1", "direction": "forward", "length": "30"}
```

**`pointOfIntersectionArcs`** — one of the (up to two) intersection points of two arcs.
```json
{"op": "pointOfIntersectionArcs", "name": "X1", "firstArc": "Arc1", "secondArc": "Arc2", "crossPoint": "firstPoint"}
```

**`pointOfIntersectionCircles`** — one of the (up to two) intersection points of two circles
defined by center + radius.
```json
{"op": "pointOfIntersectionCircles", "name": "X2", "firstCircleCenter": "A", "secondCircleCenter": "B", "firstCircleRadius": "50", "secondCircleRadius": "60", "crossPoint": "firstPoint"}
```

**`pointOfIntersectionCurves`** — intersection point of two curves, disambiguated by which
extreme point is wanted.
```json
{"op": "pointOfIntersectionCurves", "name": "X3", "firstCurve": "Curve1", "secondCurve": "Curve2", "vCrossPoint": "highestPoint", "hCrossPoint": "leftmostPoint"}
```

**`curveIntersectAxis`** — point where a ray from a base point at a formula angle crosses a curve
(or an arc — this also covers what's sometimes called "arcIntersectAxis"; there is no separate op).
```json
{"op": "curveIntersectAxis", "name": "X4", "basePoint": "A", "curve": "Curve1", "angle": "45"}
```

**`pointFromCircleAndTangent`** — tangent point from an external point onto a circle.
```json
{"op": "pointFromCircleAndTangent", "name": "T1", "circleCenter": "A", "circleRadius": "40", "tangentPoint": "B", "crossPoint": "firstPoint"}
```

**`pointFromArcAndTangent`** — tangent point from an external point onto an arc (no formula).
```json
{"op": "pointFromArcAndTangent", "name": "T2", "arc": "Arc1", "tangentPoint": "B", "crossPoint": "firstPoint"}
```

**`triangle`** — point on an axis line where a right angle forms with a hypotenuse (no formula).
```json
{"op": "triangle", "name": "Tr", "axisP1": "A", "axisP2": "B", "firstPoint": "C", "secondPoint": "D"}
```

**`height`** — perpendicular projection of a point onto a line (no formula).
```json
{"op": "height", "name": "H", "basePoint": "C", "p1Line": "A", "p2Line": "B"}
```

## Lines and curves

**`line`** — straight line between two existing points.
```json
{"op": "line", "firstPoint": "A", "secondPoint": "B"}
```

**`spline`** — quadratic spline between two points with formula tangent angles/handle lengths.
```json
{"op": "spline", "point1": "A", "point4": "B", "angle1": "0", "angle2": "180", "length1": "30", "length2": "30"}
```

**`splinePath`** — multi-point spline path.
```json
{"op": "splinePath", "points": [{"point": "A", "angle1": "0", "angle2": "180", "length1": "30", "length2": "30"}, {"point": "B", "angle1": "0", "angle2": "180", "length1": "30", "length2": "30"}]}
```

**`cubicBezier`** — cubic bezier curve from four named control points (no formula).
```json
{"op": "cubicBezier", "point1": "A", "point2": "CP1", "point3": "CP2", "point4": "B"}
```

**`cubicBezierPath`** — multi-segment cubic bezier path from a flat list of named points.
```json
{"op": "cubicBezierPath", "points": ["A", "CP1", "CP2", "B", "CP3", "CP4", "C"]}
```

**`arc`** — arc by center, radius, and two formula angles.
```json
{"op": "arc", "center": "A", "radius": "50", "f1": "0", "f2": "90"}
```

**`arcWithLength`** — arc by center, radius, start angle, and a formula arc length.
```json
{"op": "arcWithLength", "center": "A", "radius": "50", "f1": "0", "length": "78.5"}
```

**`ellipticalArc`** — elliptical arc by center, two radii, two formula angles, and a rotation
angle.
```json
{"op": "ellipticalArc", "center": "A", "radius1": "60", "radius2": "30", "f1": "0", "f2": "180", "rotationAngle": "0"}
```

## Operations

Every op below (except `group`) takes `"sourceObjects"` (any geometry type, not just points) and a
required `"suffix"` used to name each newly-created object from its source (source `"A1"` + suffix
`"_m"` → new object `"A1_m"`), and returns `{"created": [{"id","name"}, ...], "op"}`.

**`move`** — translate + optionally rotate a set of objects.
```json
{"op": "move", "sourceObjects": ["A", "B"], "suffix": "_m", "length": "20", "angle": "0", "rotationAngle": "0"}
```

**`rotation`** — rotate a set of objects around a required origin point.
```json
{"op": "rotation", "sourceObjects": ["A", "B"], "suffix": "_r", "origin": "A", "angle": "90"}
```

**`mirrorByLine`** — mirror a set of objects across a line defined by two points.
```json
{"op": "mirrorByLine", "sourceObjects": ["A", "B"], "suffix": "_mir", "firstLinePoint": "A", "secondLinePoint": "B"}
```

**`mirrorByAxis`** — mirror a set of objects across a vertical/horizontal axis through a point.
```json
{"op": "mirrorByAxis", "sourceObjects": ["A", "B"], "suffix": "_ax", "originPoint": "A", "axisType": "vertical"}
```

**`group`** — record a named group of existing objects (pure DOM bookkeeping, no new geometry).
```json
{"op": "group", "name": "Notches", "sourceObjects": ["A", "B"]}
```

**`trueDarts`** — find a dart's two base points' true (folded) positions.
```json
{"op": "trueDarts", "point1Name": "T1", "point2Name": "T2", "baseLineP1": "A", "baseLineP2": "B", "dartP1": "D1", "dartP2": "D2", "dartP3": "D3"}
```

## Pieces

**`piece.addPatternPiece`** — assemble a closed set of ≥3 named points into a pattern piece.
```json
{"op": "piece.addPatternPiece", "name": "Front", "nodes": ["A", "B", "C", "D"], "seamAllowanceWidth": "10"}
```

**`piece.addAnchorPoint`** — attach an existing point as a label anchor on a piece.
```json
{"op": "piece.addAnchorPoint", "point": "A", "piece": "Front"}
```

**`piece.internalPath`** — add an internal (not necessarily closed) path to a piece.
```json
{"op": "piece.internalPath", "piece": "Front", "nodes": ["A", "B"]}
```

**`piece.insertNodes`** — insert additional nodes into an existing piece's path. *Known gap:* can
surface a caught (non-fatal) `VExceptionBadId` in some cases — see `piece_handlers.h`.
```json
{"op": "piece.insertNodes", "piece": "Front", "nodes": ["E"]}
```

**`piece.union`** — fuse two pieces along one edge each. **Known gap: reproducibly segfaults —
do not rely on this op yet.** See `piece_handlers.h`'s own comment for the investigation notes.
```json
{"op": "piece.union", "piece1": "Front", "piece2": "Back", "piece1EdgeIndex": 0, "piece2EdgeIndex": 0}
```

## Measurements

**`measurements.load`** — swap the active measurement file (validates, does not recompute).
```json
{"op": "measurements.load", "path": "sizes.smis"}
```

**`measurements.recompute`** — re-evaluate every formula and rebuild geometry against the current
measurement variables.
```json
{"op": "measurements.recompute"}
```

**`measurements.sync`** — `measurements.load` immediately followed by `measurements.recompute`.
```json
{"op": "measurements.sync", "path": "sizes.smis"}
```

## Session lifecycle

**`session.save`** — write the current pattern document to a `.val` file (relative paths resolve
against `--output-dir`). The in-script equivalent of the one-shot CLI's `--save-pattern` flag.
```json
{"op": "session.save", "path": "square.val"}
```

**`session.close`** — always succeeds; after this batch's response is written, the daemon's read
loop exits.
```json
{"op": "session.close"}
```
